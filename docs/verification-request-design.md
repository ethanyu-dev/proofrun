# v2 请求归属与报告汇总

一次提交的多个 case 属于一个稳定 requestId。case 保留独立环境、运行身份和预算，每个 case 当前关联一个 LLM 执行。公开接口见 [Case API v2](public-api-v2.md)，读取实现见 [请求模块](../apps/api/src/modules/requests/README.md)。

## 身份与幂等

requestId 标识一次逻辑提交；caseId 标识原始业务定义；taskId 标识具体运行；stepId 和 criterionId 分别定位步骤及验收项。HTTP 重试使用原身份，重新验证创建新运行身份。

请求与 case 是持久关联关系，不能靠前端当前页分组推断。新请求显式引用已存在的相同 case 时显示复用及原执行时间，不宣称本次重新验证。请求归属不改变原 case 定义哈希，不提供 case 间依赖，也不共享账号、浏览器或预算。

原始请求和成员关系保存在 pr_verification_requests、pr_verification_request_cases；pr_request_runs 视图统一读取当前关联。重复提交、重跑和取消沿用既有事务及幂等规则。

## 聚合与覆盖

列表由 pr_request_summaries 提供摘要；详情和导出由服务端一致性快照读取成员、定义、任务和报告。generatedAt 与 aggregationVersion 标记快照和算法版本，页面及导出不拼接不同时间的事实。

唯一业务验收项按 case 和原 criterionId 统计，每个 case 只关联一个 LLM 结果。任一确认失败使汇总结论不通过，全部 case 通过才通过，缺报告或未完成必须明确显示覆盖缺口，不能把已有部分通过当成全通过。

报告生命周期、业务 verdict 与浏览器清理状态分别展示。基础设施错误、环境阻塞和证据不足不直接改写为产品失败；cleanup 不改变已确认的业务结论。byExecutionMode 只包含 LLM 的统计。

## Console 与重跑

任务和报告默认按请求组织，保留未归组任务、执行明细及单次报告入口。报告展示当前运行的验收结果、执行原因与证据。验收项关联真实附件，截图通过认证接口读取并核对摘要。

控制台整体或单 case 重跑保留原 requestId，只为选定成员新增运行，并原子更新该请求的当前运行关联。测试报告读取各成员最新关联的运行结果；未选成员与其他共享请求不变，旧任务和证据继续保留。完整映射和预算作为持久幂等摘要，旧操作重试不会回退当前运行。显式指定新 requestId 的旧 API 调用仍创建独立请求。新运行统一使用 LLM。默认按当前预算编译，原预算的兼容限制见公开协议。重跑不覆盖历史报告，部分失败不能偷偷降低原要求。

归档、软删除和摘要刷新继续遵守成员关系与资源关闭约束。运行中或浏览器尚未确认关闭时不能删除；其他可见请求仍引用的执行不会随请求删除而被移除。证据清理后原结论保留，但证据入口明确不可用。

## 验证

请求测试覆盖重复提交、复用、重跑、冻结成员、部分报告、唯一项计数及摘要刷新。数据库与 UI 夹具只证明关联和聚合规则，不证明浏览器执行或模型语义判断。
