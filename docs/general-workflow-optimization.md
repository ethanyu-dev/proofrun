# 通用任务进度与混合决策优化

本轮实现用于通用浏览器任务，不包含白名单业务名称、目标选项或页面 URL。原任务及 acceptanceCriteria 不会被改写；LLM 和 JEV 共用执行器中的步骤证据、完成校验和循环止损。

## 执行机制

1. `execution/workflow.ts` 从 objective 的行首显式编号提取步骤，延续行随步骤保留，完整 objective 中的约束仍交给模型。超过 32 步或无明确编号时保留整体原文，避免猜测拆分；简单任务不增加独立规划请求。
2. 当前阶段由 activeStep 指向。模型可以调整访问顺序，但不能删除原要求。模型工具的可选 workflow 元数据随正常决定返回，不另发浏览器命令、不授予额外权限。
3. workflow.assessments 为原步骤声明 complete、incomplete 或 blocked。complete 必须引用当前执行已登记的证据并附事实说明；其余状态可无证据，但不能算完成。全部更新先校验再保存；多步骤任务仍有未完成状态时拒绝 verification.finish。activeStep 可重新进入已记录步骤，显式重新评估可以撤销不充分的完成声明。原 criterionId 完整性和证据类型校验继续保留。
4. workflow.recovery 保存局部目标、区域描述、检索词、成功条件和 1–6 次动作预算。成功执行 browser.act 后扣减，普通观察不扣减；同一计划重送不能续期。计划耗尽后继续操作会被拒绝，需完成取证、更换计划或停止；人工接管后清除旧恢复计划。
5. JEV 按当前步骤与恢复策略排序候选。区域来自隔离 DOM 的真实 composed 祖先，包含最近区域、最多四层区域祖先以及 frame；同名表单可通过上下文区分。区域是排序信号，未知 portal、其他区域导航及退出入口不被硬删除，原有总预算裁剪仍显式报告。
6. JEV 不再仅因连续六轮就调用文本模型。有效恢复预算内先执行恢复计划；缺口、停滞、预算不足、VERIFY 或恢复耗尽时才审查。VERIFY 用于当前阶段证据检查与推进，全部阶段已记录时直接进入最终文本审查，省去一次 JEV 选择。
7. JEV 历史最多保留八个状态，每份文本从最多 16,000 字符压至 2,000 字符并标注裁剪。当前 DOM、原要求和带来源的完成记录仍保留，不把摘要缺失当作目标不存在。
8. 导航后若观察只有菜单/链接/普通元素外壳且没有输入、选择或滚动能力，最多进行两次间隔 300ms 的补采。该启发式不保证业务就绪；等待有界、不调用模型、不清除既有循环记录。
9. 公共差分器保存最近八个语义状态；第三次返回相同状态提示恢复，交替循环中第四次返回且没有新增步骤证据时以 NO_PROGRESS 停止。连续完全无变化仍沿用六轮上限。新 target 编号、重新规划和被动等待不能重置循环；步骤首次记录完成证据后才开启新的进展窗口，撤销再完成同一步不能反复清空循环计数。

## 一次正常决策携带的进度示例

```json
{
  "action": "click",
  "target": "dom-current",
  "workflow": {
    "assessments": [
      {
        "stepId": "step-1",
        "outcome": "complete",
        "evidenceRefs": ["existing-artifact-id"],
        "summary": "已观察到当前任务要求的目录信息"
      }
    ],
    "recovery": {
      "goal": "定位详情中的状态控件",
      "scope": "详情",
      "terms": ["状态"],
      "successCondition": "详情区域显示可读取的状态控件",
      "maxActions": 3
    }
  }
}
```

这只是浏览器动作工具的参数示例，实际 target 与 evidenceRefs 必须来自当前执行。完成声明只能描述动作之前已经取得的事实，不能预先认领同一次点击的结果。恢复计划不保存可重放的旧 target，每轮仍重新采集。

## 适用边界

- recorded 表示模型提交了有合法来源的完成声明，不是程序证明业务结论为真。执行器能核对身份、证据归属、预算和顺序，业务语义仍依赖模型与真实证据。
- 没有对自由文本进行额外 LLM 预规划。此类任务保留完整要求，并在正常文本决策/恢复时给出局部计划；复杂隐含分支仍需要模型理解。
- 原始编号步骤可以内部包含多个动作；执行器不通过关键词自动判定其成功条件，也不擅自新增结构化 acceptanceCriteria。
- portal 与触发器关系未知时保留未知；没有根据几何猜测控件属于哪个表单。区域路径仅作排序，不用于动作授权。
- 循环识别是有界语义状态启发式；动态噪声或需要多次返回同一页的任务仍需结合阶段证据判断，不保证识别所有无效操作。
- 恢复计划保存在当前执行进程中，并随模型上下文/回复进入现有审计记录；没有新增跨进程任务恢复协议。
- 未在真实供应商上重新运行对照任务，不能据夹具声称已实现特定提速比例。应以相同完整任务范围重复测量总耗时、文本回退次数、重复动作及证据覆盖。

- 真实页面 CDP 取样确认：选值后的命中节点是输入框局部包装内的选值展示 span。浏览器节点增加复合 combobox 命中检查，仅接受两层局部包装内的唯一交互控件、紧贴输入框的布局及非交互展示层。规则不依赖业务文案、URL 或 CSS 类名；外部遮罩、相邻独立按钮仍被拒绝。复杂或无法确认归属的组件仍保守返回遮挡，不强制点击。
- 工作流未完成与恢复预算耗尽分别返回 WORKFLOW_INCOMPLETE / WORKFLOW_RECOVERY_EXHAUSTED，给予有界恢复机会。连续三次无法恢复交付 BLOCKED，报告 verdict 为 null、标准为 SKIPPED，保留原因与已有证据，不再算模型格式错误或业务验收通过。
