# ADR 0002：Rust 节点包装 agent-browser

状态：采用为首个引擎方向；生产可用性待端到端验证。

Rust 负责节点连接、容量、会话监管和进程生命周期。agent-browser 负责浏览器观察与操作。执行 Agent 和报告协议不直接依赖 CLI 返回格式。

## 已有独立 POC

2026-09-23，在本地 macOS arm64 使用 agent-browser 0.38.1、Chrome 153、50 行 Rust JSONL worker，完成正常表单、两层 open Shadow DOM、异步结果、双会话页面状态隔离、增量快照、截图和关闭检查。

Shadow DOM 内部填写与提交成功，但 `wait --text` 等待内部状态文本超时；明确遍历 open shadow roots 的 `wait --fn` 条件通过。只补等待，未重放业务提交。服务端记录确认总共两次提交。

7 轮预热测量中，相同三条读取命令的逐条调用中位数 19.14 ms，batch 为 7.64 ms。这只是本地调用开销，无模型和远端链路，不能推断端到端速度或生产吞吐。双会话并存不等于并发负载验证。

两个 daemon 及当次观察到的 24 个相关进程全部关闭。该实验不是租约、强制取消、崩溃恢复或 Linux VM 验证。

## 适配层需要补足

- 白名单化的结构化操作、参数映射和错误分类。
- 会话身份、观察版本和动作与证据的关联。
- 命令截止时间、输出限额与取消后的实际浏览器关闭。
- 写入响应未知的核实流程，明确禁止不加区分的自动重试。
- Shadow DOM 条件等待、业务就绪状态和证据稳定性。
- 引擎版本与真实场景回归；依赖更新后重新验证。

当前工程已实现结构化适配、观察目标映射、期限、输出限额和 open Shadow DOM 条件等待，并完成真实引擎冒烟测试。Linux 上另用故障夹具验证进程关闭与恢复；验证范围见 [Browser Node 验证记录](../browser-node-validation.md)。不自动安装浏览器，不开放 CLI 透传；未知写入的引擎级验证尚未完成。

节点进程模型、依赖选择、命令去重和引擎内部重试的验证要求，统一维护在 [Browser Node 架构设计](../browser-node-design.md) 中。
