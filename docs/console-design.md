# Console 视觉规范：x.ai 样式复用

研究日期：2026-09-24。此规范是后续 Console 迁移的视觉基线。

## 1. 参考范围与结论

主参考为 [x.ai 官网](https://x.ai/)，本次页面标题为 SpaceXAI。实际打开页面，检查首屏、页面结构和浏览器计算样式；桌面视口为 1280 × 720，移动视口为 390 × 844，并切换深色模式测量配色。补充阅读 [API 页面](https://x.ai/api) 的信息结构，未访问登录后的 x.ai Console。

采用官网当前的白色背景、暖灰面板、黑白主按钮、胶囊形操作、紧凑导航、大字号标题和大留白；深色模式沿用相同结构，通过语义变量转换颜色。ProofRun 使用自己的名称和业务内容。

“完全复用样式风格”的执行约束：所有后续页面共用本规范和样式变量，颜色、字体层级、边框、圆角、按钮与动效保持一致。具体的任务列表、节点容量、证据报告按照 ProofRun 的业务信息组织。官网自定义字体尚未引入，当前不能宣称字体或像素完全一致。

## 3. ProofRun 的适配规则

下列是平台实现决策，并非声称原站具有这些后台组件或参数。

- 默认浅色，提供深色切换。页面、面板、按钮通过语义颜色变量实现；深色模式不做整页滤镜反转。
- 本批使用本机无衬线字体和等宽字体，不加载远端字体服务。中文首屏行高调整为桌面 `1.14`、移动端 `1.25`，避免照搬英文行高挤压汉字。日后若引入字体，统一替换字体变量，并重新验证中文和数字宽度。
- 用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 80px` 作为通用间距。首页最大内容宽 `1440px`；工作台可使用可用宽度，长文字和表单保持可读行宽。
- `700px` 为本项目单列断点，`1000px` 为中等尺寸的间距调整点。这是实现选择，原站精确断点没有测量。
- 主按钮黑白反差，次按钮暖灰，弱操作使用文字按钮。只有真正的按钮和可点击链接具有悬停反馈；待接入标签不伪装成可点击操作。
- `16px` 用于大面板，`8px` 用于输入框和嵌套控件。面板使用背景层次和细边框，常规内容不添加重投影。
- 主文字保持高对比；辅助文字和边框是不同语义，不能用边框的低透明度显示正文。
- 悬停颜色变化使用 `150ms`，支持 `prefers-reduced-motion`。业务数据刷新不做文字轮换；操作进度以实际请求状态驱动。
- 品牌、正文与导航保持黑白灰。后续通过、失败、阻塞等状态可以使用少量语义色，必须同时显示文字，不能仅靠颜色表达结论。

## 4. 迁移到业务页面

| 页面/组件 | 组织方式                                                         | 必须保留的业务语义                                         |
| --------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| 全局框架  | 64px 顶栏；任务、节点、报告作为主导航；面包屑和页标题在内容区    | 没有 Spec Runtime 或 Spec 分析入口                         |
| 任务列表  | 页面标题 28–32px；一个主要操作；筛选条和轻分割线表格             | 状态、所属节点池、时间、执行结果可追踪；未接入与空列表区分 |
| 提交任务  | 纵向分组表单；环境、目标、验收标准和执行限制分区；输入高 40–44px | 接收和校验已定义标准；不把新建任务做成 Spec 生成器         |
| 任务详情  | 任务摘要 + 执行记录；轻量页签切换证据和报告                      | 排队、执行、取消、阻塞、执行错误和产品验收失败需明确区分   |
| 节点列表  | 暖灰面板/轻表格；容量以数字和简洁进度显示                        | 内网归属、节点池、连接状态、会话占用；真实 API 数据为准    |
| 报告      | 结论摘要在顶部；验收项列表和证据预览并排，窄屏上下排列           | 每项结论关联证据；执行不完整不显示“验证通过”               |
| 证据查看  | 截图保持原色与比例；日志使用等宽字体；元数据使用辅助文字         | 深色主题不能改变证据图片；显示证据归属与时间               |

任务列表、提交表单、详情、报告和节点查询已按本规范迁移；节点管理与人工介入继续按协议能力推进。工作台数据区域缩小标题和垂直留白，保持同一视觉语言和可用的信息密度。

## 5. 实现边界

沿用 React + Vite + TypeScript 和原生 CSS，本批没有引入 UI 套件、CSS 框架或动画依赖。

- `apps/console/src/tokens.css`：字体、语义颜色、圆角、间距、动效以及主题变量的唯一入口。
- `apps/console/src/style.css`：共享导航、按钮、表格、面板与响应式布局。
- `apps/console/src/main.tsx`：连接、路由和全局导航；页面位于 `pages/`，共享组件位于 `components/`。主题仅在当前页面内切换，刷新恢复浅色；持久偏好留给后续用户设置。
- 业务数据从真实 API 读取；加载、空结果、读取失败和未登录独立展示，不在应用中内置模拟结果。
- 共享组件保持少量且职责明确；状态标签、页标题、空状态和读取状态已提取，按钮共用样式。

## 6. 验证与后续验收

首次首页视觉基线的历史验证结果：

- `pnpm --filter @proofrun/console build` 通过，包含 TypeScript 检查和生产打包。
- 1280 × 720 桌面：三列卡片宽约 402.66px、左右边距 24px；主标题 60px；浅色和深色首屏均已查看。
- 390 × 844：卡片为 358px 单列，标题 36px，页面宽度无溢出；深色首屏已查看。
- 320 × 740：页面与视口宽均为 320px；检查可见元素无左右越界，浅色首屏已查看。
- 鼠标点击与键盘空格均能切换主题，按钮的按下状态与页面主题同步。
- 全部页内链接均存在目标；实际点击“查看工作台”后定位至工作台区域。
- 浏览器未捕获到错误或警告。响应式检查结束后恢复默认视口。

这覆盖首次首页基线的构建与基本交互，不覆盖所有浏览器、完整无障碍审计、系统缩减动效模拟、持久主题偏好或业务接口。

后续业务页面验收：桌面与窄屏不横向溢出；深浅主题均可读；键盘焦点可见；缩减动效偏好有效；所有主要入口均可操作；输入、错误与结果有文字说明。业务接口未连接时明确显示未接入，接口失败时明确显示错误，不能用空列表掩盖故障。

视觉检查不代表任务执行、节点管理、报告查询或真实模型业务验收已经完成；这些按原有迁移计划独立推进。

业务页面迁移验证见 [测试入口与覆盖边界](../tests/README.md)。

## 7. 验证报告

`#/reports` 为报告列表，显示统一结论、验收项统计、证据保留情况和执行结束时间。`#/reports/{taskId}` 是单次执行的独立报告页，任务详情保留显式入口；报告页提供返回任务详情的链接。对照任务的每组仍拥有独立身份和报告，不合并结论。

阅读顺序为总体结论与未覆盖范围、逐项验收与关联证据、折叠的执行步骤及全部证据、报告溯源。未通过项优先，通过项默认折叠。现有协议只保存合并的逐项 summary，页面显示“本次观察与判定依据”，不将一段原文伪装成两份独立事实。截图缩略图与预览都走认证接口并核对摘要；侧栏保留验收项上下文，支持 Escape 关闭和焦点返回。证据清理后禁用查看入口，结论保留。

报告状态与公开 API 的 reportStatus 一致，取 PASSED、FAILED、INCONCLUSIVE；无报告为 null。任务生命周期、执行阻塞/错误单独显示。导出 JSON 附带相同状态与验收统计，保留原始报告内容。状态计算与接口兼容规则见公开 API 文档。
