已为 apps/api 实现 PostgreSQL 持久化、节点配对、主动 WebSocket 网关、全局队列、容量预留、worker 租约、证据存储和报告校验。使用真实 Rust Node 与固定执行器验证了执行闭环，范围见 [控制面验证记录](control-plane-validation.md)。

apps/agent 已实现任务领取、远端导航预检、有界模型循环、逐项验收和报告。模型保持可配置，测试使用本地协议夹具，范围见 [Agent 验证记录](agent-validation.md)。Console 已接入任务列表、提交/取消、详情、节点注册/撤销/轮换、人工介入、操作记录与证据报告；节点登录存储复用、网络元数据和维护工具已实现，使用说明见 [迁移交付记录](migration-completion.md)。接下来需要实际模型做业务质量验收；不引入 Spec Runtime。本地 Linux Chromium 场景已通过；节点仍需完成实际内网 VM 联调、引擎响应丢失写入验证、记录保留与主机重启恢复工具的实际 VM 演练。写操作默认不开放，不能把节点去重测试当成引擎 exactly-once 证明。

## 1. 一条真实任务闭环

Console 迁移统一遵循 [x.ai 样式研究与视觉规范](console-design.md)。当前已交付任务列表与筛选分页、提交/取消、任务详情、报告证据读取和节点状态查询，覆盖范围见 [Console 验证记录](console-validation.md)。节点配对/撤销/轮换、人工介入与登录复用已实现；不把协议夹具当成真实业务验收。

Browser Node 内部按 [节点设计中的实施顺序](browser-node-design.md#14-实施与验收顺序) 推进：先验证 Linux 会话关闭和引擎重试边界，再实现命令可靠性、远端接入和证据交付。

1. 完善任务、节点能力、注册、心跳、租约和会话协议，建立 TS/Rust 同源消息类型。
2. 建立任务持久化和队列，注册一个可主动连接控制面的 Linux 内网节点。
3. 实现 Rust 会话监管和 agent-browser 适配，固定引擎版本。
4. 执行 Agent 领取任务，调用浏览器并评价已有验收项。
5. 交付可追溯到具体操作、会话和验收项的证据报告。

验收：真实内网 VM 完成一次表单提交；业务服务确认只写入一次；报告引用真实证据；结束后进程和配额正确释放。当前本地 POC 不能代替此验收。

## 2. 可靠性闭环

实现容量准入、并发会话隔离、取消、截止时间、节点失联、租约 fencing、进程崩溃和重启恢复、证据交付确认。

验收：断连或旧 worker 晚到结果不能推进新任务；写入响应丢失不会自动重复提交；未知关闭不能释放已占用的资源；报告区分产品失败与执行失败。

## 3. 真实业务覆盖

登录存储、受限人工操作、网络元数据、报告浏览和节点维护已补齐；复杂 Shadow DOM、虚拟列表与各业务登录流程仍需具体场景验收。对照旧项目的关键场景评估成功率、耗时、模型 token、失败原因和清理完整性。

验收：使用同一组任务和环境比较，不以 CLI 微基准推断整场任务提速。达到约定的真实场景质量后再替换旧平台。
