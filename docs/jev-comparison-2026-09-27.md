# JEV 与当前模型的真实对比记录

日期：2026-09-27。已实际请求模型服务，共 48 次：3 次 JEV 初测、36 次配对比较、9 次原 Agent 协议复测。所有请求均获得可解析的有效决定，无自动重试；浏览器动作数为 0。

## 结论

JEV 在这批页面状态上的建议耗时较低，简单表单和明确栏目切换表现稳定。复杂页面上的定向搜索框选择连续失败，不适合据此直接接管全部动作。适合继续推进可选建议模式，并改进决策视图与候选构造后再测。

本次测的是“真实模型 + 真实页面历史观察”的下一步建议。没有重新执行完整业务任务，没有验证 JEV 能独立完成 GLM 价格整理；不能把动作预期命中率当作完整任务成功率。

## 1. 输入与实验方式

来源任务：

- `real-model-smoke-675c0260`：此前成功的普通表单任务，三个真实浏览器状态分别是空输入框、已填入 Ada-ProofRun、显示 Saved Plain Ada-ProofRun；原任务另保存一次 Plain 提交的服务端记录。
- `novita-glm-pricing-bfb1f1c8`：此前完成的公开定价页任务。旧报告标记 PASSED，但全页面覆盖存在缺口，本次只使用其中的 DOM，不把旧结论作为完整性真值。

每份源 DOM 均核对原报告中的 SHA-256。五个状态在调用前指定预期动作；第六个完整 GLM 目标没有唯一动作标签，作为探索项单独列出。

配对比较中，双方获得相同的页面状态、目标、规则与角色候选，每个状态重复三次，交替先后顺序，串行调用。JEV 请求 `jev-latest`，实际返回 `jev-1.13.0`；文本模型配置为 `openai/gpt-5.6-sol`，实际返回 `gpt-5.6-sol`。

文本模型通过一个专用 `choose_action` 工具输出操作与目标。这与当前生产 Agent 的完整六工具协议不同，因此另做原协议复测，不能把配对比较直接说成生产 Agent 的能力排名。

页面文字最多 6,000 字符，明确标记截断。Novita 搜索状态提供了 233 个点击候选、1 个填写候选。历史数据没有完整可见性、字段能力和视口边界信息，候选只按角色筛选；不保证这些历史候选可在实时页面执行。

## 2. 同输入比较：各 18 次请求

“命中”指同时选中预先指定的操作和目标；填写值不属于本轮比较范围。

| 页面状态与预期                      |         JEV 命中 |     文本模型命中 | JEV 中位耗时 | 文本模型中位耗时 |
| ----------------------------------- | ---------------: | ---------------: | -----------: | ---------------: |
| 空表单 → 填写 Plain name            |              3/3 |              3/3 |       718 ms |         2,283 ms |
| 已填写 → 点击 Save Plain            |              3/3 |              1/3 |       553 ms |         5,439 ms |
| 已保存 → 请求验收                   |              3/3 |              0/3 |       406 ms |         3,057 ms |
| 指定定位 Search models → 填写搜索框 |              0/3 |              1/3 |     1,051 ms |        25,727 ms |
| Dedicated → 切换 Serverless         |              3/3 |              3/3 |       618 ms |         2,604 ms |
| 完整 GLM 目标的下一步，探索项       | 均选择填写搜索框 | 均选择填写搜索框 |       842 ms |         5,157 ms |

| 汇总指标                  |        JEV | 当前文本模型，专用选择接口 |
| ------------------------- | ---------: | -------------------------: |
| 有标签状态的严格命中      | 12/15，80% |                8/15，53.3% |
| 全部请求                  |         18 |                         18 |
| 协议或网络错误            |          0 |                          0 |
| 全部请求中位耗时          |   648.5 ms |                   4,125 ms |
| 全部请求 P95，最近秩法    |   1,333 ms |                  29,927 ms |
| 服务返回的输入 token 合计 |    105,048 |                     63,681 |
| 服务返回的输出 token 合计 |     18,411 |                      1,860 |

耗时包括请求、接收及响应校验；不包括浏览器、文字填写值生成、信息抽取、LLM 对 JEV 建议的审核或最终验收。每种模型仅 18 次，P95 在这个样本量下等于最大值。重复请求可能受到连接复用和缓存影响；此结果不是冷启动或大样本性能承诺。

不同服务的分词和计量方式可能不同。JEV 的多问题概率分布回复较大，本轮返回的 token 数更多。没有取得可比较的实际账单金额，不能推导“JEV 成本更低”。

### 具体失败

JEV 在明确要求定位 Search models 的三次测试中，分别选择点击 Learn More、Filter by LLM、Filter by LLM。操作置信度为 0.48、0.59、0.56；对应目标置信度为 0.11、0.14、0.15。

完整 GLM 目标下，JEV 三次都选择 Search models，但操作置信度只有 0.38、0.42、0.39。这说明任务措辞和上下文构造会影响选择；不能设置一个未经校准的固定置信度阈值就宣称可靠。

文本模型的专用选择接口在已填写或已保存状态上多次重复选择填写。它也在搜索框定向测试中选择了 Filter by All 或 BLOCKED。这些结果包括适配方式的影响，需要结合原协议复测解释。

## 3. 原 Agent 协议复测：9 次请求

直接使用当前 `ChatModel` 的原系统提示、六工具协议与响应校验器。只重放三个表单状态，每个三次；输入含原任务、当前 DOM 和有效证据引用，没有重建原运行的历史命令。这是独立状态复测，不是原成功轨迹的完整复现。

| 表单状态 | 严格命中 | 实际情况                                            |
| -------- | -------: | --------------------------------------------------- |
| 空表单   |      3/3 | 都选择填写 Plain name，值为 Ada-ProofRun            |
| 已填写   |      3/3 | 都选择点击 Save Plain                               |
| 已保存   |      1/3 | 一次完成，一次再次点击 Save Plain，一次请求额外观察 |

合计严格命中 7/9，中位耗时 4,131 ms；输入 14,493 token，输出 656 token。

额外观察属于谨慎补证，不应直接归为业务错误；再次点击保存则有重复提交风险，本次未真正执行。单次状态回放缺少历史操作，因此不能将这两项结果直接等同于原运行会重复提交或最终失败。

原协议明显改善了已填写状态的选择，说明比较结果受工具接口与上下文影响。不能用专用选择接口的 8/15 宣称当前完整 Agent 的任务成功率只有 53.3%。

## 4. 对 ProofRun 设计的影响

1. 继续采用可选建议模式。此次只有测试脚本调用 JEV，运行中的 Agent 默认策略没有改变。
2. 优先改进动作视图：提供当前字段值、可用操作、可见范围、当前子目标和进度；验证候选裁剪，避免把完整页数百个链接都交给下一步选择。
3. 独立记录操作置信度和目标置信度。低质量建议交回 LLM；阈值应通过更多任务校准。
4. 保留已执行操作和完成证据。原协议复测也展示了缺少历史时的重复动作风险。
5. 下一阶段做完整闭环：从同一初始页面分别运行原策略与建议策略，计入所有模型、浏览器和验收耗时，使用独立的服务端状态与覆盖检查判断任务成功。

这些是基于本轮结果的后续建议，本次尚未实施候选优化、建议审核或 JEV 直接执行。
