- 采集、执行器上下文及 JEV 候选分别报告缺口。正文达到上限后仍继续识别控件，控件达到上限后仍继续采集正文；原生 select 超过 200 项会报告省略。尚无选项续读接口。

### 变化优先的实现细节

节点层保留上一份有界观察的比较摘要，比较键包含文档代次、frame 身份和 backend node 身份。公开 target 仍绑定当前 observation，比较键不成为跨轮操作凭据。当前每轮重建 CDP 连接，不能直接把连接内 session ID 当跨轮稳定身份；需映射到稳定 frame/target 身份。

识别 `added`、`becameVisible`、`textChanged`、`valueChanged`、`expandedChanged`、`enabledChanged`、`removed`。虚拟列表复用节点但改变选项文字/value，也视为变化。导航后比较基线失效，当前页按首次观察处理。缺失范围被裁剪时标记未知，不能把未采集到的节点误记为 removed。

先按操作与区域关系分组，再按以下优先级排序：

1. 与上一步操作相关的新弹层、下拉、校验提示和变化控件，以及它们的局部正文。
2. 活动弹层内仍有效的未变化控件，尤其确认、取消、关闭等退出路径。
3. 当前焦点/表单、与任务有关的其余当前控件。
4. 其他可见控件及简短页面导航。

操作后出现不代表由操作引起：保留“时间上后出现”和“有关联”的事实，不伪造因果。时间戳、动画、广告、轮询数字等变化要降权；后台持续变化不能压过当前弹窗。临时 target 重编号不计为变化。

变化对象同时进入正文摘要与可执行候选，统一引用当前元素表。只改变正文顺序却仍把候选截成旧前 80 个，无法解决问题。removed 只进入变化摘要，不进入可执行目标。没有变化时保留当前有效控件，并显式输出 noMeaningfulChange，不能发空上下文。

完整目标输入组织如下；这是后续结构示意，第一阶段实际字段以代码及上方实现范围为准：

```text
state = {
  goal, acceptanceProgress,
  lastAction: {operation, target, executionResult},
  changes: {addedRefs, updatedRefs, removedSummary, changedRegions},
  elements: [变化控件及活动区域优先的当前元素，描述只保存一份],
  page: {url, title, changedText, relevantText},
  coverage: {capture, text, candidates, unloadedRegions},
  recentActions
}
```

元素保留 name/role/value/checked/expanded/disabled/允许动作和必要的区域关系；去掉候选中重复的完整 DOM 文本行。questions 按 ID 和简短语义引用 elements，不再重复整段字段描述；必须用回放验证这种压缩不会降低目标选择准确率。

### 放宽限制的边界

2026-09-28 核查的官方模型文档：`jev-latest` 指向 `jev-1.13.0`；整请求上限 64k token，state 加最长单个 question 上限 32k token。单个 Choice 最多 255 项。[模型约束](https://docs.typesafe.ai/models)、[Choice 限额](https://docs.typesafe.ai/api#choice)。

因此本地 `JEV_REQUEST_CHARS=32000` 不是模型的 32k token 上限，应改为同时检查每问题和整请求预算。没有准确 tokenizer 时，使用经中英文实际 usage 校准的保守估算，保留余量；不得套用固定四字符一 token。实际模型版本要随调用记录，避免 latest 升级后无法复现。

首期仍可保留现有单问题动作候选协议，先把目标动作软上限从 80 调至 200；服务预算允许时可进一步到 250，但必须满足“动作候选＋控制候选总和不超过 255”。当前五个控制候选可容纳 250 个动作；增加补全入口后要相应减少。目标数、动作数不得混用。

后续把 operation 与 click/type/select target 分成同请求的独立问题，每个目标问题单独遵守 255 限额。它们并行独立求值，不能让 target 问题依赖 operation 的返回值，而应问“若执行该操作，应选择哪个目标”。超限按区域缩小或读取下一批；不能为了装下更多项把未发送项声称为不存在。

多问题主要改善职责分离，不保证 token 更少；上游也在元素表和问题中重复了一些描述，应结合我们自己的请求测量决定压缩格式。

### 第一阶段落地与验证

实现顺序调整为：目标滚动修复 → 节点比较摘要与变化标记 → 正文/候选统一排序去重 → 放宽数量及预算 → 模型可见的覆盖缺口 → 共用停滞恢复。独立 query/read 与分页缓存作为第二阶段兜底。

新增回放/夹具范围：DOM 尾部新弹层优先；未变化取消按钮保留；虚拟列表复用节点识别内容变化；导航和编号变化不误报；截断不误报删除；无变化仍有可操作候选；250 动作加控制项不越过 255；变化项超预算时明确未发送范围。夹具只证明这些机制，真实白名单场景仍需重跑确认。

## 1. 目标与现有问题

目标：模型拿到精简观察后，能知道哪些信息被省略，按范围检索、读取或推动页面展示，并根据真实变化决定是否继续。LLM 和 JEV 共用同一机制。

2026-09-28 的白名单对照任务暴露了三个问题：带目标的滚动丢失了目标、JEV 前 80 个候选被普通元素占满、停滞反馈未形成强制恢复或终止。

改动前的链路还存在独立的信息损失：

- `crates/browser-node/src/engine/dom.rs`：正文、目标数和目标描述字节各有上限，却共用一个 `truncated`；达到目标数上限会终止后续正文遍历；原生 select 的选项只取前 200 项，缺少选项续读信息。
- `apps/agent/src/execution/runner.ts`：上下文超限时继续裁剪正文和目标，只有整体裁剪标记，无法定位被省略的区域。
- `apps/agent/src/model/jev.ts`：候选只取前 80 个，允许通用 `element`，中文业务名称不参与现有英文词相关性评分；combobox 没有直接进入当前可点击角色集合。
- `apps/agent/src/model/jev-progress.ts`：检测停滞后转交 LLM 并重置计数，不能保证执行最终退出循环。

## 2. 完整性必须按层、按范围描述

| 情况                        | 如何识别                           | 补全方式                           | 不能据此得出的结论           |
| --------------------------- | ---------------------------------- | ---------------------------------- | ---------------------------- |
| 已采集内容未发送            | 缓存索引中存在，响应标记分页或裁剪 | 查询缓存、读取子树或下一页         | 模型没看到不等于页面没有     |
| 节点采集达到上限            | 采集层记录正文、节点或字节限额     | 缩小范围重新采集；超限明确失败     | 当前快照覆盖整页             |
| 目标未进入候选              | 目标索引存在，候选排除原因可查     | 按角色、名称、区域检索并生成候选   | JEV 无候选不等于不可操作     |
| 下拉未展开、虚拟列表未渲染  | 展开状态、滚动指标、渲染项发生变化 | 展开或针对实际滚动容器滚动，再观察 | 隐藏数据已经完成界面验收     |
| iframe 或 shadow 范围未覆盖 | 每个范围有采集状态或具体错误       | 指定范围读取；失败保留原因         | 局部读取成功等于全部范围成功 |
| Canvas 等没有可读语义       | 画面存在而语义目标不足             | 当前截图与视觉操作，或人工介入     | 可以由模型猜造 DOM           |

每份观察分别提供 `captureCoverage`、`deliveryCoverage`、`candidateCoverage`，不再让单个布尔值承担所有含义。覆盖对象须包含范围、已返回数量、已知总数、限制原因和续读入口；不知道总数时返回未知，不能填成已返回数量。

“完整”仅指指定快照、指定范围、指定读取类型已穷尽。虚拟列表抵达滚动底部只是一项观察事实，不自动证明服务端不存在更多数据。

## 3. 观察与补全接口

第二阶段建议保留 `browser.observe`，新增只读的 `browser.query` 和 `browser.read`。第一阶段先完成上文的变化优先、候选扩容与覆盖说明。以下为拟议接口，不是当前可调用能力。

```text
browser.observe({scope?, screenshot?})
  → snapshotId, observationId, generation, regions, targets,
    captureCoverage, deliveryCoverage, artifactRefs

browser.query({snapshotId, scope?, role?, name?, cursor?, limit?})
  → matches, coverage, nextCursor

browser.read({snapshotId, scope, section, cursor?, limit?})
  → nodes/text/options, coverage, nextCursor, artifactRefs
```

`scope` 使用节点签发的文档、frame、区域或元素引用；`section` 限定为正文、子树、目标或原生选项等封闭类型。不允许模型传入任意脚本。`query` 默认使用有界的字面名称检索，不依赖模型自行创造元素编号。

### 3.1 节点内保留有界索引

采集后先建立文档、父子关系、区域、文本和目标索引，再生成发给模型的精简视图。缓存按会话隔离，设置字节、节点数、有效期和总容量上限，结束会话时释放。

节点采集上限与模型上下文上限分离。缓存自身不完整时，查询必须返回局部覆盖，不能把缓存搜索无结果解释为页面无结果。

正文和可操作目标分别限额；一个达到上限不应静默终止另一类采集。原生选项、frame 失败、名称截断等分别记录，不只标记整份观察。

### 3.2 快照续读与页面更新分开

同一快照的分页从固定缓存读取，保证不因动态 DOM 改变导致跳项或重复。游标绑定会话、快照、范围、查询条件和位置；错配、过期或超限明确返回错误。

补全页与原观察共享快照身份，返回内容记录证据引用或可审计的原始证据范围。历史快照仍可用于说明当时所见，但其中目标不自动获得当前操作资格。

任何动作、导航、人工接管恢复后重新观察。异步页面更新时，在动作前重验真实节点、文档代次、连接状态、必要的语义状态及命中位置。不能仅靠 MutationObserver 或节点仍连接就宣称观察未过期。

需要跨范围重新采集时生成新观察，明确替换当前操作目标表；禁止将旧的 `dom-393` 按编号绑定到新快照里的另一节点。

### 3.3 默认视图保留什么

默认先返回相对上一轮观察的相关变化，再返回活动弹窗/下拉、当前焦点、可见业务控件、关键状态和页面区域摘要；未变化的必要控件仍保留。正文、目标和截图各有预算；第一阶段扩大有效信息覆盖，仍无法容纳的细节在第二阶段通过补全获取。

目标描述增加职责明确的字段：`scopeRef`、`frameRef`、`parentRef`、`expanded`、`disabled`、`selected`、`controls`、可见性、可操作能力及滚动容器引用。未知字段保持未知。

区分“存在布局”“在视口内”“可被命中”；现有布局存在不能直接等同于用户可点击。继承的 `cursor:pointer`、伪元素和图标子节点只作为弱线索，避免把整棵子树都提升为独立点击候选。

## 4. 虚拟列表与目标滚动

必须先修复动作语义：`scroll(target=...)` 显式解析目标，不能降级为没有目标的页面滚动。无目标滚动继续保留页面级语义；指定目标找不到真实滚动区域时返回可解释错误。

下拉的 ARIA listbox 可能是隐藏的辅助节点，真正滚动区域也可能在 portal 中。优先利用 `aria-controls` 等明确关联；再结合活动弹层、范围、几何和命中信息寻找滚动区域。关联含糊时返回多个候选供选择，不能默认滚动最近祖先或整个页面。

滚动使用定位后的真实输入路径，并核实目标命中和滚动后的事实。返回：

```text
dispatch: completed | rejected | unknown
scroll: {containerRef, before, after, moved, atEnd}
content: {renderedItemsChanged, newItemCount, loadingObserved}
```

输入派发成功与内容有进展分别记录。若发生滚动后仍等待加载，进行有界条件等待并重新观察；输入效果未知时沿用当前终止规则，不自动重放。

虚拟列表逐窗口采集选项，按可用的稳定业务标识、value 或明确限定范围的标签去重。禁止按复用的 DOM 节点身份去重：同一节点可能先后代表不同选项。历史汇总保留每项来源，当前点击仍需要新观察中的目标。

本例的正确路径：展开搜索下拉 → 定位实际选项滚动区域 → 逐窗口读取，直到两项均取得证据 → 关闭下拉 → 打开新增弹窗 → 在弹窗范围核对类型及默认开关 → 关闭弹窗。表格行中出现两个类型不能替代下拉选项存在的证据。

## 5. JEV 候选与公共恢复状态机

### 5.1 候选生成

先比较观察并识别相关变化范围，再做可操作性过滤和排序。变化控件和相关正文最优先，同时保留活动弹层的未变化操作、当前表单和明确业务按钮；合并按钮内部图标等重复点击目标。保留真正有独立交互行为的自定义控件，不能简单删除所有 div。

支持 combobox、listbox、option 等控件关系；无法直接执行的控件交给补全或 LLM。中文相关性采用原始业务短语匹配及可配置分词/字符片段，避免仅提取英文词。

候选预算仍有上限，但按区域与角色分配名额，返回省略数量和检索入口。JEV 候选缺失时先按任务范围检索；LLM 的降级上下文也使用同一索引，不重复发送整页历史。

已因遮挡或无进展失败的“范围＋目标语义＋动作”在页面状态未变化前暂时排除，避免重新生成同一个失败候选。

### 5.2 公共恢复流程

```text
观察 → 检查覆盖 → 查询/读取补全 → 决策 → 执行动作 → 比较实际变化
                                                    ↓ 无进展
                              定向补全 → 更换策略 → 人工介入/保守结束
```

恢复逻辑放在执行器公共层，JEV 与纯 LLM 都受约束。起始阈值建议：连续 2 次相同动作无有效变化进入恢复；同一停滞阶段最多尝试 3 种有区别的恢复策略，仍无进展则请求允许的人工介入，或输出未完成/无法确定。

阈值为初始配置，需要通过回放校准。显式等待异步加载可使用独立等待预算，但不能无限豁免。重复计数不会因为调用 LLM、截图、重新编号或重新规划而清零。

进展同时考虑目标范围的语义变化、实际滚动位置、渲染项窗口、展开/加载状态及验收项新增证据。截图光标闪烁、时间文字变化、单纯增加调用次数都不算业务进展；滚动位置变化也不等于验收完成。

补全调用单独计量，并受每阶段读取次数、累计字节和任务截止时间约束。为最终报告和资源回收预留时间，避免所有预算消耗在重复操作中。

## 6. 实施顺序与验收

1. **修复当前阻塞及观察组织**：目标滚动、跨轮变化标记、正文与候选统一排序去重、放宽候选预算、模型可见的分层缺口、公共无进展恢复上限；不依赖完整补全协议即可先落地。
2. **打通补全协议**：更新契约源及生成类型、节点快照索引、查询/续读命令、控制面转发、证据落盘、Agent 工具和上下文组装。旧节点通过能力声明识别；缺少能力时明确降级，不能伪造完整覆盖。
3. **提升动态控件覆盖**：滚动区域关系、虚拟列表累计证据、frame/弹层范围读取、控制台覆盖状态与停滞原因展示。

验证分层执行，不把夹具通过表述为真实后台验收：

| 验证层           | 必须覆盖                                                                                                                                           | 不代表什么                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| 单元/契约        | 分层裁剪标记、游标绑定与过期、中文匹配、候选去重、停滞预算不能被重规划重置                                                                         | 不证明真实浏览器能滚动         |
| 真实浏览器夹具   | 目标位于第 80/2000 项之后、超过 200 个原生选项、portal 下拉、隐藏 ARIA listbox、虚拟列表节点复用、动态重渲染、iframe、遮挡、内容不变但滚动位置变化 | 不证明生产组件和登录链路已通过 |
| 本次业务场景重跑 | 两种模式分别完成搜索下拉两项取证、新增弹窗两项取证、默认开关记录、关闭弹窗且未提交；完整留存动作与证据                                             | 不泛化为全部网站可用           |

建议把任务步骤拆成独立验收项。当前只配置一个“搜索下拉包含两项”的验收条件，不能完整约束新增弹窗、默认开关和关闭未提交等要求。

观测指标包括：各层省略原因、补全成功率、重复动作次数、恢复成功率、实际新内容数量、两种模式的模型调用与 token、逐项证据覆盖。成功标准首先是任务完成和证据正确，再比较速度与成本。
