# 独立人工处理页

HITL 从管理员操作面板迁移为任务专属页面。处理者无需登录 ProofRun，只看到本次待办和当前浏览器画面；链接本身是短期操作凭据。没有 Spec Runtime，人工不修改上层验收标准，也不能直接生成 PASSED。

## 使用流程

1. 上层任务设置 `environment.allowIntervention: true`。调度器只选择具有 `liveView` 能力的 Browser Node。
2. 当前步骤明确要求已登录账号且可见页面仍有登录表单或登录页人机验证时，执行器会在模型操作前主动请求人工。每步最多自动触发一次；访客、退出登录、仅检查登录页的步骤不会触发。未授权介入时明确受阻，人工等待仍计入原预算。其他场景执行 Agent 使用 `verification.intervene` 提供 `reason` 和可选 `items`；管理员也可在任务详情请求介入。未传 items 时使用原因作为单项待办。
3. API 在同一事务中进入 REQUESTED、生成介入记录和专属链接。原 worker 到达无在途命令的安全点后确认 HUMAN。
4. 控制台点击“打开独立处理页”；也可把处理链接交给处理者。页面没有平台导航、任务列表、报告列表或管理凭据输入。
5. 处理者点击画面、输入、滚动或使用按键完成登录和其他事项。中文/粘贴可使用页面的输入框；启用登录复用时也可以提前显式保存登录状态。
6. 勾选待办并点击“保存登录状态并继续任务”。服务端等待已接收输入完成，保存节点私有登录快照，确认结果后才恢复 AUTO。未启用登录复用时仍显示“完成，继续任务”。保存失败保留 HUMAN 并显示错误；回执未知时重连只追踪原命令。Agent 恢复后重新观察原浏览器，任务页自动重连只读画面。
7. 页面尝试自动关闭；浏览器不允许关闭时显示完成页。这里关闭的是人工处理 tab，原浏览器 session 保留到验证任务结束。

仅关闭处理页不会恢复 Agent。有效期内可用同一链接重新进入；输入不自动重放。同一时间只允许一个处理连接，另一处理页会被拒绝。输入结果未知时停止后续操作，遵循已有任务故障和资源回收规则。

## 通过 Cookie 完成本次登录

独立处理页的“通过 Cookie 登录”支持逐项输入已授权账号的名称和值。写入的是本次任务原浏览器会话，权限只在 HUMAN 状态和当前控制代次有效；Agent、只读观看页、过期链接均不能写入。目标 origin 固定为任务目标站点，不允许改写其他站点或指定任意 domain。

Cookie 使用 host-only、根路径 `/`、SameSite=Lax 和会话有效期，HTTPS 站点启用 Secure。默认 HttpOnly；站点前端需要读取时可取消。输入必须是有效的 Cookie 名称和值，不接受整段 `Cookie:` 请求头或任意脚本；多项可逐个提交。写入仅计为一个人工动作，沿用原预算、串行队列及 commandId 去重。等待操作确认后再完成接管；不确定结果不自动重放。

默认勾选“写入成功后刷新远端页面”。组合操作整体入队，仅在写入成功回执后刷新；失败、断线或未知结果不会继续刷新，也不自动重放。多项 Cookie 可在最后一项勾选刷新。刷新额外计一个动作，仍受任务总预算限制。

当前步骤要求登录时，无论模型介入发生在登录表单还是只有登录入口的业务页，恢复后 Agent 都重新访问当前步骤目标 URL 并采集证据；Cookie 写入成功不等于登录或业务验收成功。完成接管时是否保存共享快照仍遵循原任务登录复用设置。Cookie 功能需要 Browser Node 支持 `browser.cookies.set`；新增导航和刷新复用现有节点协议。

Cookie 值不进入 CLI 参数、操作回执、活动摘要或模型工具上下文；原始人工命令仍按现有命令持久化和保留策略存储。填写区使用密码输入，提交后清空，不写入 URL 或前端持久存储。

## 远端导航与操作焦点

独立处理页提供“前往远端网址”和“刷新远端页面”，复用当前任务会话。地址框表示人工输入的目的地，不是远端实时地址栏；仅允许不含账号密码的 HTTP/HTTPS URL。服务端仅开放 navigate/reload，不开放任意 browser.act 或脚本。导航与刷新遵守原控制代次、单会话串行、命令去重与任务预算；Cookie 写入范围仍固定为任务 origin。

点击或键盘聚焦画面后，浏览器区域出现蓝色轮廓和“键盘输入将发送到远端”提示。点击外部、“退出键盘控制”、切换窗口或页面隐藏会解除提示；不在全局捕获键盘。轮廓不占内容尺寸，不改变坐标映射。

左侧显示授权剩余时间，最后一分钟突出提示，到期禁用操作。倒计时不延长原任务时限，重新连接不能复活已关闭的会话。

## 登录状态复用

新任务表单默认开启“自动复用本站登录状态”（`environment.reuseAuth: true`）。旧任务未设置该字段时，默认跟随 `allowIntervention`；可显式设置 `reuseAuth: false` 关闭自动复用。自动槽位由环境 ID、资源池和目标 URL 的 origin 确定。自动记录的节点仅是调度偏好：命中域名路由时使用路由节点；未命中时优先使用最近一次成功分配的节点，节点离线、满载、撤销或能力不足时允许使用其他合格节点。切换节点后只恢复新节点本地已有的状态，无文件时从空状态开始，按任务前置条件重新登录或请求人工介入；不会复制、删除旧节点的登录文件。必须使用某一节点上的账号状态时请显式指定 `environment.auth`。不同账号请使用不同环境 ID 或显式命名槽位。

显式 `environment.auth` 优先，包含 `nodeId`、`stateId`、`restore`。`restore: true` 仍严格要求已有快照，`restore: false` 表示本次从空白浏览器开始；自动模式则在文件存在时恢复，首次无文件允许人工登录。损坏文件不会被当作“尚未登录”静默忽略。

每次会话都创建独立 profile，结束后仍删除该 profile。跨任务保存的是节点私有 Cookie/localStorage 存储快照，不保证站点的服务端会话永不失效，也不保存完整浏览器目录。HITL 完成时保存，普通自动任务不会隐式回写运行中状态。

并行两组使用同一轮次的不可变初始快照，首次无快照的空状态也被固定。启用登录复用时，两组固定到本轮首次分配的节点，第一组结束后仍保留该约束；其他独立任务更新自动偏好不会改变本轮归属。节点暂时不可用或满载时等待；本轮节点与后续域名路由冲突时返回排队诊断，需要恢复配置或新建对照。即使第一组先登录并保存，第二组仍从本轮固定初始状态启动；下一轮任务才读取更新。共享槽位保存使用跨进程文件锁与版本比较：先成功更新者生效，仍基于旧版本的另一组返回“保留较新快照”，不会覆盖它。同一会话成功保存后可再次保存自己的后续更新。

快照内容不上传控制面、不进入模型上下文和报告。控制面只持久化槽位的节点偏好与执行节点身份；节点以私有权限写入并原子替换快照。同轮初始快照保留至少 48 小时，后续访问该槽位时清理过期轮次文件。

## 接口和授权

- 管理员：`GET /v1/admin/executions/:id/intervention`。
- 本次执行者：`GET /v1/executions/:id/intervention`，使用执行租约令牌。
- 返回 `{ intervention: { id, items, expiresAt, path, url } }`；没有有效介入时为 null。
- 处理页：`/#/hitl/<id>/<token>`。token 留在 URL fragment，通过 `/v1/hitl/connect` 的首条消息认证，不进入 HTTP 请求路径、查询参数或节点。
- 节点：另建主动连接 `/v1/hitl/relay`，使用原节点凭据及服务端刚下发的临时 streamId，不能任意选择其他会话。

链接最长有效 30 分钟，且不超过原任务截止时间；worker 必须保持原租约。完成、取消、租约失效、任务超时或控制代次变化会撤销操作权。旧链接不能访问其他任务或管理员接口，完成后重开只返回完成状态。平台管理员密钥轮换后，不应依赖旧链接的重新派生；已经持有的旧链接仍受原有效期和任务状态约束。

本地 Console 与 API 分端口时，设置 `PROOFRUN_CONSOLE_URL=http://127.0.0.1:5173` 生成可打开的链接。生产默认使用 `PROOFRUN_PUBLIC_URL` 的同源 HTTPS 页面和 WSS。Vite 开发代理已开启 WebSocket；Caddy 的 `/v1/*` 转发覆盖两个新连接入口。

## 节点与实时通道

复用固定 agent-browser 0.38.1 的本机 streaming 服务。Node 仅为允许介入的任务确保流服务可用，读取该会话私有目录中的端口元数据，不开放 VM 入站端口。原生服务仅绑定回环地址。

浏览器画面经 `Node → API → 处理页` 中转，最多请求 8 帧/秒，单帧限制 2 MiB；慢处理页丢弃旧画面。此通道只转发当前视口图像，不转发原生 dashboard、浏览器标签列表、CDP 或任意引擎消息。画面不写入命令 outbox 或报告证据库。

人工输入使用新增的封闭 `browser.input` 操作（click/text/press/scroll），沿用持久命令、commandId 去重、原操作预算与单会话串行。每次输入算一个动作；连续英文键入在页面短暂合并后提交，中文或粘贴可整段提交。普通 Agent 不允许提交此人工专用操作。

处理页相邻的待发送滚动会合并，避免触控板连续事件塞满输入队列；点击与按键保持原顺序。画面背压只丢弃旧帧，不能静默丢弃操作回执、错误或完成通知。输入超过 25 秒、完成交接超过 30 秒未确认时关闭连接并提供重连入口，重连前应先检查页面状态，未确认输入不会自动重放。

启用实时画面的新会话会显式同步 Chromium 与流服务的初始视口为 1280×720；后续视口修改仍走引擎命令。处理页使用 JPEG 自身比例显示，点击按显示区域映射到远端视口，边框不占用坐标区域。升级前创建的会话不自动改变视口，需要创建新会话使用该初始化修复。

调用 `mouse move/down/up`、`keyboard inserttext` 和受限 `press`；前导短横线用字符 `-` 按键处理（物理键名 Minus 不会插入文本），不能被解释为 CLI 参数。没有把客户端事件直接透传给 CDP。任意一步的未知结果都不重放。操作摘要不返回输入内容；原始命令仍按平台既有持久化与保留策略管理。

## 验证

```sh
pnpm check
PROOFRUN_TEST_DATABASE_URL='<独立测试库>' pnpm test:api
PROOFRUN_TEST_DATABASE_URL='<独立测试库>' pnpm test:agent:integration
PROOFRUN_TEST_AGENT_BROWSER=/absolute/path/agent-browser-linux-arm64 pnpm test:hitl:linux
```

新增 API 集成场景覆盖：非法链接、越权读取拒绝、单处理者、等待交接、画面中转、拒绝会话管理命令、输入去重与共享预算、断线重进、完成撤权、新旧介入隔离和取消失效。模型请求人工与恢复后的报告仍由 Agent/API 集成覆盖；这些测试中的模型和节点是协议夹具。

浏览器页面联调使用独立临时数据库，确认无需平台登录、仅显示当前待办和画面、提交输入、完成页及交接。内嵌浏览器限制自动关页，页面提供完成页回退，不能保证所有浏览器均能自动关闭。

Linux 测试使用真实 Rust Node、systemd、agent-browser 和 Chromium，检查真实 JPEG 帧、坐标点击、中文与前导短横线输入、按键、业务提交次数、完成后原 session 仍可观察和最终关闭。模型/执行者是夹具，回环连接用 WS，不代表生产 TLS、真实内网、业务 SSO/MFA 或真实模型验收。

测试镜像固定 Rust 1.98.0，避免浮动补丁版本隐式触发下载。网络受限时可显式使用缓存镜像、工具链和只读 Cargo registry，测试日志会输出实际 cargo 版本：`PROOFRUN_TEST_SKIP_IMAGE_BUILD=true`、`PROOFRUN_TEST_RUST_TOOLCHAIN=1.98.1`、`PROOFRUN_TEST_CARGO_REGISTRY=/absolute/path/to/registry`。默认不启用这些覆盖。

当前提供网页视口的点击、文字、按键和滚动；不包含操作系统桌面、文件选择器、拖拽或远端浏览器标签管理。业务弹窗、多标签 SSO 等场景需要单独验证，不能从普通登录夹具推断全部支持。

## 控制权与执行代次

`AUTO → REQUESTED → HUMAN → AUTO` 是同一次执行的控制权状态，不是新的任务生命周期。管理员和模型均只能为 `environment.allowIntervention: true` 的任务请求人工辅助。REQUESTED 立即阻止新自动操作；worker 等在途命令完成，在安全点确认后进入 HUMAN。只有管理员能恢复 AUTO。

暂停和恢复都更新 controlRevision。命令及报告绑定该代次；旧页面不能在新的人工会话里操作，旧模型回复不能在人工改动后继续执行。恢复后重新观察，重新进行模型判断。所有人工动作共享原 maxActions 和 deadline；原 worker 必须持续续租。worker 丢失、取消或总预算耗尽都会停止执行，不以人为活动延长权限。

Console 提供观察/截图、导航、点击、填写、按键、滚动和保存绑定登录状态；不提供任意脚本、shell、CDP 地址或直接会话续租。页面操作不能更改验收项，人工也不能直接写入 PASSED 结论。命令输入和 DOM 可能含业务内容，管理员接口仍需部署在受控入口；登录快照本身不上传控制面。

## 显式登录快照

上层任务可选择：

```json
{
  "environment": {
    "id": "staging",
    "nodePool": "internal",
    "allowIntervention": true,
    "auth": {
      "nodeId": "registered-node-id",
      "stateId": "qa-account",
      "restore": true
    }
  }
}
```

首次人工登录用 `restore: false`，任务进入人工控制后完成登录，再点击保存当前登录状态。后续任务用 `restore: true`。状态保存在对应节点 `home/auth/qa-account.json`，文件 0600、目录 0700，原子替换；每次执行仍创建独立 profile。任务队列只会选择指定节点；与域名路由冲突时保留排队并提供 `AUTH_NODE_ROUTE_CONFLICT` 诊断。相同槽位允许多个独立 profile 并发执行，保存时仍受版本比较保护。

也可在停止节点后导入已有存储状态：

```sh
proofrun-node --config /etc/proofrun/node.toml auth-import --state-id qa-account --file /private/auth.json
proofrun-node --config /etc/proofrun/node.toml auth-forget --state-id qa-account
```

导入文件必须仅运行用户可读，且包含 cookies/origins。状态失效时由模型请求人工或明确阻塞，不自动提交登录口令，不保证 sessionStorage、跨域 SSO、设备绑定或 MFA 的跨会话有效性。
