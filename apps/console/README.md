# proofrun-console

React + Vite 控制台。已接入真实控制面 API：任务列表、搜索与状态筛选、游标分页、任务提交与取消、任务详情、验收报告、DOM/PNG/NETWORK 证据预览、报告 JSON 导出、节点注册/撤销/轮换、人工介入与操作记录。

界面采用 [shadcn/ui](https://ui.shadcn.com/)（Radix）和 Sonner，保持简洁的管理台布局。深浅主题共用 `src/tokens.css`，使用本机字体；主题切换在当前页面生效。组件与布局约定见 [控制台设计](../../docs/console-design.md)。没有 Spec 分析、验收标准生成或执行 Agent 的第二份状态机。

任务与报告统一使用「验证任务」列表，每个请求的「查看详情」下方提供「验证报告」入口。报告详情保留独立地址，旧 `#/reports` 列表地址兼容展示统一列表；主导航不再提供重复的报告列表，页面不显示 footer。

## 本机运行

先按 [API 说明](../api/README.md) 启动 PostgreSQL 与 API，再运行：

```sh
pnpm --filter @proofrun/contracts build
pnpm dev:console
```

打开终端给出的地址，在页面输入 API 的 `PROOFRUN_ADMIN_TOKEN`。连接验证成功后，凭据保存在当前站点的浏览器 localStorage，刷新或重新打开时会自动验证已保存凭据，成功后恢复当前路由，无需再次点击连接；验证期间显示恢复状态。验证失败会展示原因并允许手动重试，不覆盖已保存凭据。主动断开连接或取消自动连接后暂停自动恢复（刷新后仍有效），仅自动填入凭据，手动连接成功后重新启用自动恢复。连接页可通过「清除已保存凭据」移除本地记录。本地存储受限时仍可连接，并提示保存失败。凭据不进入 URL、构建包或 Vite 环境变量。

开发服务器默认将 `/v1`、`/v2` 和 `/health` 代理到 `http://127.0.0.1:4100`。API 端口不同时，在启动前设置服务端环境变量 `PROOFRUN_API_PROXY`。改动配置后重启 Vite。不要在代理层注入固定管理员凭据，也不要使用 `VITE_*` 配置密钥。

生产构建使用 `pnpm --filter @proofrun/console build`。发布 `dist` 后，部署入口需要将 `/v1`、`/v2` 转发到同源 API；远端访问使用 HTTPS。Vite 开发代理不属于生产构建，单独运行静态预览不能代替 API 代理。当前没有 SSO、多租户或面向公网用户的会话管理。

## 模块边界

| 文件                              | 职责                                             |
| --------------------------------- | ------------------------------------------------ |
| `src/main.tsx`                    | 连接状态、页内路由、页面按需加载                 |
| `src/components/app-shell.tsx`    | 全局导航、连接状态和内容布局                     |
| `src/components/ui/`              | shadcn 基础控件与 Sonner                         |
| `src/components/select-field.tsx` | 业务下拉封装与空筛选值映射                       |
| `src/components/modal.tsx`        | 弹窗忙碌保护、关闭和焦点归还                     |
| `src/components/connect.tsx`      | 手动连接、启动时验证并恢复凭据                   |
| `src/credential-storage.ts`       | 凭据记忆与主动断开后的自动恢复开关               |
| `src/api.ts`                      | 同源请求、超时与错误；证据限额和摘要核对         |
| `src/use-resource.ts`             | 当前页面轮询、取消旧请求、成功数据与读取错误分离 |
| `src/pages/request-list.tsx`      | 验证请求索引与报告入口；筛选变化重置游标         |
| `src/pages/task-submit.tsx`       | 提交上层已定义 JSON，不生成标准                  |
| `src/pages/task-detail.tsx`       | 任务事实、独立清理状态、逐项结论和证据入口       |
| `src/pages/nodes.tsx`             | 节点连接、能力、占用、配对和撤销                 |
| `src/components`                  | 共享状态/布局、证据预览、报告导出                |

页面只在可见时每 5 秒继续轮询，前一次结束后才调度下一次。翻到后续列表页时暂停自动刷新，返回第一页恢复。页面切换和断开连接会中止读取，迟到结果不覆盖新任务。失败时保留上次成功数据并明确提示错误和读取时间。

任务提交与取消不自动重试。请求未确认时保留输入，先查询任务 ID；同 ID 同定义才可幂等重提。取消只撤销后续执行，不能回滚已发生的业务写入。浏览器关闭确认单独展示。

证据通过同源 ID 读取，不跟随报告中的 URI。校验大小、类型与 SHA-256 后展示，DOM 以纯文本处理。证据选择变化时取消旧读取并释放对象 URL。报告导出先提供完整 JSON 预览，再提供复制和下载入口。

## 验证看板

导航「验证看板」（`#/dashboard`）提供提交 Case 数、通过 Case 数、Case 通过率和 Tokens 总消耗。默认展示本周，可切换日、自然周、自然月，选择历史日期或前后浏览周期；趋势始终按天展示，点击柱形或明细日期进入日看板。北京时间统计，周一为一周首日。当前周期沿用可见页面轮询，历史周期手动刷新；读取失败保留上次成功结果并提示错误。

Case 按首次提交日归属，展示当前执行结果；重复提交、复用及同 case 重跑不增加 Case 数，结果取最新未删除运行；运行次数按每次提交日另计。历史双跑以 JEV 组判定，普通单组按实际结果，独立清理不增加 Case 数。通过率为「通过 / 已结束」，已结束包含失败、无结论、取消、受阻和异常，排队与执行中不进入分母；无已结束 Case 显示 `—`，周、月直接用周期总数计算，不平均每日百分比。

Tokens 按服务端接收每次调用的日期统计，包含全部执行组、清理和重试。用量构成展示验证执行的输入、输出、合计及调用次数。尚未上报的用量明确标记，不能当作零；旧报告没有逐次调用记录时，汇总用量按任务结束日回填并显示回填数量。Case 日期与 Tokens 日期相互独立，历史 Case 结果可能随执行完成而更新。

接口与迁移见 [API 看板说明](../api/README.md#验证看板统计)。`apps/api/test/dashboard.test.ts` 使用独立 PostgreSQL 验证日期边界、复用去重、双跑及用量归属；`tests/console/dashboard.test.ts` 验证周期交互、过期响应隔离和错误展示。测试数据为注入夹具，不证明真实模型调用或业务验收。

## 界面组件

`components.json` 配置 shadcn 的源码目录与别名。基础控件来自官方 new-york-v4 注册表，并适配中文文案及现有语义颜色；上游许可证保留在 `src/components/ui/LICENSE.md`。Tailwind 4 仅提供组件工具类，不启用全局 preflight，避免改变报告、证据和业务表格的排版。

按钮及按钮式链接使用 `Button`，输入与多行文本使用 `Input` / `Textarea`，下拉使用 `SelectField`。不得新增原生 select、window.alert 或 window.confirm。取消任务、撤销节点、证据预览使用共享 Dialog；提交版本使用 Tabs，切换保留页面草稿。成功操作用 Sonner 提示，错误继续在相关表单或弹窗内展示。

`tests/console/ui-controls.test.ts` 使用 DOM 夹具验证键盘选择、空筛选值、表单值、禁用状态、弹窗忙碌保护及焦点归还；不代表真实 API、浏览器布局或业务验收。

## 验证

请求报告的顶部汇总展示验证执行的时间、Tokens 合计及 JEV/LLM 拆分，可展开“用量明细”查看输入、输出、合计和调用次数。API 和 JSON 导出的总用量仅包含验证执行。

请求任务详情展示验证目标、准备/验证/清理步骤、步骤完成进度及执行操作入口，重跑也从任务页发起；请求报告展示总体结论、逐项结果和证据，并提供报告导出。两页通过顶部“查看验证报告 / 查看任务详情”互相跳转，不再提供“总览与验证目标 / 测试报告”双标签。报告中的“查看执行过程”仍可追溯原执行记录。

```sh
pnpm test:console
pnpm --filter @proofrun/console build
# 使用独立 PostgreSQL，自动创建并回收临时数据库。
PROOFRUN_TEST_DATABASE_URL=postgresql://user:password@127.0.0.1:5432/proofrun pnpm test:api
```

浏览器联调夹具：确保 4100 端口空闲，设置测试数据库变量后运行 `pnpm exec tsx tests/console/serve-fixture.mjs`。页面使用该文件 `ADMIN` 常量中的临时访问凭据。脚本会准备排队、验收通过、受阻、执行错误及 DOM/PNG 证据；按 Ctrl+C 回收独立数据库和临时证据目录。所有任务标题明确标记“联调夹具”，节点是协议模拟，截图为最小 PNG，不代表真实模型或浏览器业务验收。

覆盖与未覆盖项见 [测试入口与覆盖边界](../../tests/README.md)。节点配对/撤销/轮换、人工介入、临时身份会话与操作追踪的运行边界详见 [部署与运行维护](../../deploy/README.md)。当前仍为管理员操作台，没有用户体系。

独立免登录 HITL 处理页、实时浏览器画面、受限输入和完成交接现已接入，使用与验证边界见 [HITL 说明](../../docs/hitl.md)。

## 提交验证任务

提交页默认打开「v2 Schema 提交」，只需粘贴 Schema 文件中的 case JSON 数组（1–32 个），通过 `/v2/cases` 提交。数组自动封装为请求，成功后进入请求详情。不需要填写目标、验收项或执行配置表单。控制台自动补齐缺少的 `caseId`、步骤 `policy: []` 和 setup 步骤 `expected: []`，验证步骤的预期结果仍必须提供；业务内容和显式 `session` 原样保留。

历史任务与报告列表根据服务端保存的关联标出双跑组别，操作统一为「查看详情」，分别进入任务详情和报告详情；双跑任务详情自动展示两组对比，无需单独入口。任务和报告列表只展示“通过数 / 总数”；双跑按验收项去重，任一模式通过即计入通过数，跨分页读取关联组。报告详情将 LLM 与 LLM + JEV 逐项并列为“✓ / ×”：通过显示“✓”，失败、证据不足及未验收沿用原归类显示“×”，悬停说明保留具体含义，尚无记录显示“—”，顶部呈现两种模式各自耗时，身份与证据记录下移。各模式原始报告及 JSON 导出保留各自结论；单组任务及未携带关联的旧响应不会根据任务 ID 推测另一组。

v2 仅使用 LLM，默认允许人工辅助；平台显式配置仍优先。平台需要预先配置 case 执行环境，详见 [Case 执行平台配置](../../docs/case-platform-config.md)。每个 Case 创建临时浏览器，组内步骤串行，分组绑定独占 tab，共享当前身份材料；不保存或恢复登录快照。

提交前自动生成的身份会写回输入框。请求失败或结果未确认时保留这份草稿，重试沿用同一身份；重新粘贴不带身份的原文会创建新任务。不要在结果未确认时重新生成身份。

「浏览器任务」只填写目标网址和任务目标，通过 `POST /v1/browser-tasks` 提交。任务身份自动生成；切换标签保留草稿，未知网络结果重试沿用同一身份。修改业务输入后提交使用新身份。独立列表沿用验证任务的布局，支持搜索、执行状态筛选和分页；筛选变化返回第一页。“已结束”仅指生命周期结束，不代表目标已达成。

列表保留查看详情入口，执行中额外提供实时画面入口。详情执行中优先展示实时画面，结束后优先展示任务结果，并保留操作记录、截图、证据及重跑。人工处理入口在查看操作记录时仍可使用，终态不显示过期人工待办。实时画面沿用只读帧流，不生成完整录像。浏览器任务不展示验证报告或验收通过率；旧报告书签仅对显式浏览器任务跳转到任务详情。结果 Markdown 不执行 HTML 或加载远程图片。

## 浏览器任务与历史兼容

浏览器任务使用显式 `taskKind: browser`，没有验收项；完成时交付 `browserResult`，包含完成情况、正文和本次执行证据。需要登录时按平台人工权限处理；预算由服务端冻结。验证看板仍只统计验证任务，不混入浏览器任务及其用量。

历史任务缺省任务类型，继续按原验收定义读取与重跑。旧 `POST /v1/tasks` 内部接口仍可使用；控制台不再提供完整内部任务 JSON 编辑入口。v2 提交与请求报告保持原语义。

请求列表直接展示全部 case，不再显示请求级汇总指标或展开按钮。每个 case 显示“通过数 / 验收项总数”和当前执行状态；详情中的 case 与逐项验收也直接展开。界面仅使用一组执行记录：历史双跑优先使用当前默认的 JEV 组，单组沿用实际执行。计数、状态、说明和证据始终来自同一组，不拼接另一组的通过项；运行中使用已保存步骤的验收记录。页面不呈现模式对比或程序汇总的整体业务结论，API 与 JSON 导出保留兼容字段。

## 重跑

请求任务详情在创建时间旁提供“删除记录”，全部 case 执行结束后可通过确认弹窗删除请求及当前关联执行，并从列表和统计中排除。服务端仍检查会话与清理是否结束；其他请求共享的执行保留。报告和列表不提供删除入口，也不展示历史运行区域。

请求任务详情提供“重跑整个请求”和每个成员的“重跑此 case”。点击直接提交，由服务端按各 case 判断登录需求：访客保持空白会话，需要登录时优先查询 DevPass，无可用账号则进入 HITL，不再要求逐项填写身份来源。两者都保留原 requestId 和 caseId，只新增所选 case 的运行记录；成功后留在原页刷新。测试报告读取每个成员最新关联运行的结果，未重跑成员保持原结果，新运行完成前不显示旧报告结论。旧任务与证据保留。网络响应未确认时重试沿用运行身份，确认成功后再次重跑使用新的身份。
