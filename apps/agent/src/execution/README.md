# 执行循环

`runner.ts` 负责领取后的单任务编排、封闭浏览器操作与自动刷新观察；`context.ts` 负责有界模型上下文、历史正文与裁剪标记。`lease.ts` 独立维持租约；模型调用再慢也不能阻止撤权。

`decision-support.ts` 维护执行器尚未实现的协议能力。当前 `evidence.read` 和 `browser.batch` 只保留 Schema 定义，不在模型工具列表中公布；执行端也在保存结论、更新工作流和派发命令前拒绝它们，并沿用三次模型纠错上限。浏览器派发使用显式分支，新增决定必须配套执行实现，不能透传为节点命令。

动作只经控制面发送到已分配的节点，worker 不访问业务内网。异常效果不会触发新 ID 重试；最终报告保留既定标准、已知证据和命令身份。运行方式见 [Agent 说明](../../README.md)。

两种模型共用 `prompts/action-replay.ts` 的提交规则：成功命令回执只证明动作已执行，不能证明业务成功；结果未达预期时继续只读查询或验收，不重放已执行的写入。计划成功条件尚未满足也不能清除其中已执行的动作。该约束由模型结合原始任务解释，不按按钮名称封禁点击，也不是运行时幂等保证；真实模型遵从率由测评单独验证。

`press` 不带 target 时作用于当前焦点；带 target 时必须引用当前观察，且节点声明 `viewport.targetedPress=true`，由节点聚焦并确认后再派发按键。旧节点不允许定向按键，须显式点击聚焦、重新观察再使用全局按键。`keyboard-receipt.ts` 区分请求目标 `requestedTargetName` 与节点确认的 `targetName`；`keyboard.focusVerified` 只表示按键前确认焦点，不证明 Tab 后失焦、校验提示或业务结果。缺少或不匹配的回执保留未知，不从动作成功推断焦点。

每次供应商 HTTP 请求经 `model/request.ts` 记录实际正文，包括系统指令、工具定义、裁剪后的 context 和调用参数。JEV 选择、文本审查与填写值子调用按实际请求分别编号，并关联执行循环轮次。认证头不进入记录；图片 base64 以已有截图证据引用替代，同时保存原始请求正文 SHA-256。请求存档失败时停止派发，回执交付失败时保留已保存的待回执请求并明确报错。任务详情页按模块显示正文，历史任务未保存的请求无法精确回放。

`workflow.ts` 保留原始编号步骤和有来源的完成声明，两种决策模式共用完成门槛。正常模型工具可附带 `workflow` 更新与有界恢复计划，不扩展节点动作权限。模型重规划不能清空公共循环计数或重置同一恢复预算；详见 [通用优化机制与边界](../../../../docs/general-workflow-optimization.md)。

原生 DOM 条件等待在正常读取得到否定结果时最多等待五秒，并为命令回执预留一秒。`CONDITION_NOT_MET` 只有在等待命令明确返回 `FAILED/NOT_STARTED` 时才允许重取观察，由模型核对当前状态；连续恢复仍受既有三次上限与步骤预算约束，不重放之前的业务提交。传输超时和效果未知不进入该恢复分支，也不把未命中的预期文本当作业务失败。

结构化任务由 runner.ts 按服务端规范化的 steps 串行执行；同序按输入位置稳定排列。每步使用独立模型任务视图、Workflow 和预算，租约、浏览器会话和证据仓库全程共享；步骤结果持久化后才推进下一步。显式等待不调用模型，后续清理在同一队列任务末尾使用独立预算。详见 [v2 协议](../../../../docs/public-api-v2.md)。

人工交还控制权后直接重新观察当前页面，不重新导航或刷新。同入口的连续步骤保留当前页面，包括站点重定向、语言和团队空间；步骤明确更换网址时先检查当前页面，尚未到达才导航，每步仍单独采集新证据。模型上下文的 `preconditions` 提供当前步骤适用的条件、核验来源与人工确认代次，纯 LLM 和 JEV 共用；不传递登录配方、账号池或凭据。人工确认仅证明指定前置条件，业务结论仍须逐项验收。

自动身份准备推进认证代次时仍保留待执行导航：身份准备页与业务分组页独立，新分组页必须先打开自己的入口再交接。认证变化仍使旧观察、计划和在途决定失效；只有控制代次变化才取消旧导航，以保护人工交还的页面。

普通交接和准备门禁返回时使用同一份核实反馈：有效人工确认与当前页面无冲突、且准备项全部满足即可提交准备结果，不重做登录或验证码提交。未确认或失效条件仍须处理；交还本身不能自动完成准备。

结构化步骤的 `verification.record` 会将已验证的项目立即写入步骤快照。后续 `finish` 可只补交剩余项目；`PASSED/FAILED` 不可改写，同判定重复提交为幂等。`INCONCLUSIVE/SKIPPED` 是暂存结果，必须引用本步骤新增的有效证据才可升级为通过或失败，并保留旧证据来源；历次声明正文通过模型请求与回复记录追溯。新增证据身份仅证明来源有效，不代替模型核对业务覆盖。单步受阻、模型错误或步骤预算耗尽只结束当前步，后续步骤仍按自身前置条件执行。仅撤权、取消或未知输入效果等失去安全执行条件时停止整个序列。后续清理的异常单独记录，不改变业务判定。

折叠子项的阅读进度通过 `interactionProgress.currentTargets` 绑定当前观察目标，滚动或重新编号后不复用历史 target。已登记阅读的控件默认禁止重复点击，JEV 普通点击候选直接排除这些控件；确需按原任务重查、验证开关或收起面板时，经文本模型提供 `workflow.revisitReason`，仍受点击前置检查及预算约束。恢复计划耗尽时，动作工具明确要求同时提交新的局部计划；新计划不能超过剩余步骤动作额度。切换策略后返回旧计划、调整词序或增大预算均不能恢复已消耗额度；人工交接会清除旧恢复计划。

准备阶段允许执行原任务要求的语言切换等必要页面操作。`PREPARING` 中仍有动作额度和可操作目标时，首次 `OTHER` 阻塞先交模型复核一次；真实登录、身份交接与 policy 门禁仍按原规则执行，复核不会自动放行。业务步骤每四次动作通过 `verificationReview` 提醒保存尚未确定的独立验收项，JEV 此时交文本模型审查，所有调用仍占原预算。业务 `finish` 内合法的逐项结论先持久化，再检查工作流是否完整；未完成的 FAQ 仍导致步骤受阻，不能把部分结论当整步通过。

setup 没有独立验收项时，工具约束 `criteria: []`，完成须提供本步执行证据。清理阶段可调用 `browser_cookies_clear`，平台绑定该步骤的 origin，仅允许删除清理原文明确列出的名字；节点按精确域名和所有路径删除并回读，不返回 Cookie 值。需要节点上报 `cookieCleanup` 能力，旧节点会明确返回不支持，不能把普通 DOM 观察当作 Cookie 已清除的证明。

登录与账号条件不足时，模型可用 `verification.block.reasonCode` 声明 `LOGIN_REQUIRED` 或 `IDENTITY_UNCONFIRMED`。执行器在允许人工辅助且非访客/清理场景时，先交接一次人工并重新观察当前页面；人工返回不等于业务通过。旧模型未填写原因时，仅在当前步骤明确要求登录且观察到可见登录入口时兜底交接，其他阻塞保持原处理。每步登录交接有界，不能通过重复请求无限暂停。

两种模型共用登录证据规则：残留验证码表单、登录入口和静态协助提示不能单独否定当前身份查询结果。身份不明确时优先使用任务允许的只读入口核实；新出现的未认证、会话失效或账号不符仍可推翻旧登录证据。该规则由模型解释页面证据，不通过固定账号文案或测评服务端真值强制判为登录成功。

`sessionPreconditions` 单独携带本执行已完成准备步骤中的人工确认，必须与当前认证版本一致；旧协议按控制代次隔离。当前步骤同名条件优先，旧观察、未完成准备和旧认证版本不会传递，清理与身份重核时不提供该字段的历史事实。它帮助模型理解跨步骤身份连续性，不修改当前步骤的前置门禁或业务判定。

## 统一计划模式

`planned-v1` 将模型供应商与业务路由分离。`model-router.ts` 只根据执行器快照选择文本决策或候选服务；`JevSelector` 返回动作、字段选择或结构化复核请求，不调用文本模型、不保存页面历史。文本模型同轮可保存已有结论、提交顶层 `plan` 和首个动作，最终仍由 runner 顺序校验与持久化。

定位阶段剩余三次动作时直接交回文本层，为选择和结果查询统筹原额度；普通表单计划不会仅因同样的剩余额度被打断。成功滚动后一次无变化就触发复核；定位词匹配的新可点击候选出现时也提前核对，不等待计划额度耗尽。匹配只是复核线索，不能据此认定业务成功；已消费的回执检查点不会重复触发。

`model/scroll-scope.ts` 只在计划明确命中当前唯一容器，或最近成功定向滚动仍对应当前唯一容器时，撤下 JEV 的整页滚动候选。定向滚动和 REPLAN 保留；需要切回整页时由文本层决定。重名、失效回执和不同计划范围不自动绑定，不沿用旧 target，不改变节点滚动幅度或动作预算。

`context.ts` 的类型化快照和 `boundContext` 同时服务初始请求与复核请求。对供应商的视图只保留一份顶层计划；适配器不能再覆盖另一份历史。`operation-journal.ts` 维护一个有界回执集合，近期窗口与关键回执只是投影。公共页面变化计数、验收账本、面板原文和位置索引分别保存各自事实，不由 JEV 再记一份。

路由事件、计划和执行范围随实际模型请求归档。检查点游标只在文本结果通过元数据校验后推进；后续动作失败产生新的结构化异常。身份代次即使未伴随控制代次变化，也会使正在运行的旧回复失效。原始步骤顺序、租约、未知副作用停止、逐项结论保存与人工门禁不由模型路由替代。

详细配置、兼容回滚与验证边界见 [Agent README](../../README.md#统一计划执行策略)。
